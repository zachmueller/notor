## Notes

- **Path translation finding.** The source design notes (Obsidian vault) reference `shared/notor/src/...`. That is a vault artifact and is wrong for this repo. Every path in these specs is translated to the real repo source root `src/...` (e.g. `src/chat/sub-agent-runner.ts`). This checklist and its siblings contain **zero** occurrences of `shared/notor`.
- **Inline peek card is NEW chat UI (scope risk).** `ToolResult.sub_agent_metadata` is currently rendered only by the HTML exporter (`src/export/html-exporter.ts` `renderSubAgentDetail()` ~585) — `src/ui/message-renderer.ts` `renderToolResult()` ~506 does **not** render it in the chat panel today. FR-179 / `POL-003` therefore introduces a brand-new in-panel inline peek card; treat the HTML-export markup/CSS as a reference, **not** a reuse. (Sequencing-Risk Register item 7.)
- **`orchestration_edges` is net-new.** The `Conversation` type at `src/types.ts` ~24 has no orchestration fields today; the typed-edge adjacency list and the `orchestration_step_conversation` `_type` marker are additive header fields introduced by `INT-006`, with the single contract authority in [contracts/edges.md](../contracts/edges.md). Hide step conversations from the flat sidebar the moment `FEAT-007` writes them (Sequencing-Risk Register item 4), generalizing the existing `isSubAgentFilename` / `_type` filter in `src/chat/history.ts`.
- **Per-step model is session-pinned, never global (ARCH-007 — review-resolved).** `applyProviderModelOverrides()` (`src/personas/persona-manager.ts` ~349-453) mutates the **global** `ProviderRegistry`; step turns must **not** use it. ARCH-007 adds a pure `resolvePersonaProviderConfig(...)` (mirroring `resolveWorkflowProviderConfig()` in `src/chat/workflow-executor.ts`) pinned into the `ConversationSession`, so concurrent step turns / `run_flow` children never race on model selection. See [research.md](../research.md) Finding 5 (resolved). (Sequencing-Risk Register item 13.)
- **`notor-max-iterations` counts LLM turns only (review-resolved).** It maps to `AggregateBudget.iterationsRemaining`, decremented per LLM turn. **Code steps do not count** toward it (zero tokens, not an LLM turn); a code-step-only flow/cycle is bounded by `notor-max-runtime-minutes` + stale-loop detection. Authority: [contracts/run-loop.md](../contracts/run-loop.md) + [contracts/event-engine.md](../contracts/event-engine.md).
- **Capped turns and semantic verification (review-resolved).** A non-`completed` step turn synthesizes `{step}.capped` (FR-117a), not the success topic, so a cut-off turn never silently advances. The engine has **no** semantic verifier — a `completed`-but-wrong emission is the **author's** job to gate via a verifier step (the code-step verify pattern). The stale detector catches self-loops only; multi-step cycles rely on budget + runtime (no general cycle detection in v1), and the **completion-alternation** case is now bounded cheaply by the **completion no-progress guard** (Issue-9): after `COMPLETION_NOPROGRESS_THRESHOLD` (default 3) consecutive blocked `FLOW_COMPLETE` from the same step whose blocking set did **not** shrink, the engine terminates with `FLOW_ERROR` naming the step. Authority: [contracts/event-engine.md](../contracts/event-engine.md).
- **Every flow is bounded by construction — finite ceiling defaults (Issue-8 / review-resolved).** `notor-max-iterations` / `notor-max-runtime-minutes` / `notor-max-cost-usd` are optional in frontmatter but the parser (`FEAT-002`) injects **finite** defaults when omitted — **`100` / `60` / `5.00`, NEVER `Infinity`** (constants in `src/orchestration/constants.ts`); `notor-max-depth` may stay `null` (unlimited depth is fine because the three ceilings bound total work). So no flow runs unbounded even if the author sets nothing. Authority: [data-model.md](../data-model.md) + [contracts/vault-schema.md](../contracts/vault-schema.md).
- **Orphan handling hardened — validator hard-error + recognized failure channels (Issue-10 / review-resolved).** The FR-110 load-time topology validator now **hard-errors** (was: warns) on **any published-but-unsubscribed non-terminal topic**, so a structurally-orphan-prone topology cannot run. The runtime-only failure channels `{step}.capped` / `{step}.no_emit` / `{step}.code_error` are **recognized failure channels**: unsubscribed, they are handled by the engine's **default failure handler** → a *diagnosable* `FLOW_ERROR` **naming the step**, not an anonymous `FallbackCoordinator` orphan. No fuzzy steering is added; the prevention layer is hardened. Authority: [contracts/event-engine.md](../contracts/event-engine.md).
- **Fan-out drain is breadth-first FIFO (Issue-11 / pinned engine invariant).** When a fan-out topic resolves to `[A, B, …]`, each subscriber runs in `notor-steps` order with its emission **enqueued**, and the queue is drained FIFO **only after the fan-out set is exhausted** (NOT reentrant/depth-first). This makes the `event.emitted` order deterministic for the safety detectors and FR-125 replay; `TEST-002` asserts the event-history order. Authority: [contracts/event-engine.md](../contracts/event-engine.md).
- **`run_flow` is orchestration-context-only; `origin` always set (Issue-4 / review-resolved).** `run_flow` returns `success: false` if no `orchestrationContext` is present (mirrors `emit_event`), so a foreground-chat-launched child flow (an unrecoverable orphan) cannot exist; every child flow has either a replayable `run_flow` parent or is a `chaining` recovery root. Session `origin` is **always set** at creation (never null). Authority: [contracts/tools.md](../contracts/tools.md).
- **Per-subtree rollup uses `subtreeConsumed`, not a shared-cell delta (Issue-12 / review-resolved).** `RunContext` carries a per-node `subtreeConsumed {costUsd, iterations, maxDepthReached}` accumulator (each child constructs a fresh one, folds it into the parent on settle); the **shared `AggregateBudget` cell** stays the authority for the spawn gate + root-header rollup, while `subtreeConsumed` is the authority for `child_run_metadata` per-subtree numbers (a shared-cell delta would absorb concurrent siblings' spend). Authority: [contracts/edges.md](../contracts/edges.md) + [contracts/run-loop.md](../contracts/run-loop.md).
- **`emit_event` terminal latch + emission overwrite audit (Issue-13e / review-resolved).** Within a turn, non-terminal emissions are **last-write-wins** (logged as `event.emission_overwritten`, `prev_topic` → `new_topic`); a **terminal** emit (`FLOW_COMPLETE`/`FLOW_CANCELLED`/`FLOW_ERROR`) **latches** — a later `emit_event` in the same turn returns `success: false` (the latch is also audited via `event.emission_overwritten`). New `session-log.jsonl` entry types `child.spawned` / `child.result` / `event.emission_overwritten`; `turn.complete` now carries `cost_usd` + `token_usage`. Authority: [contracts/tools.md](../contracts/tools.md) + [data-model.md](../data-model.md).
- **Iteration-counter naming (Issue-13c).** `session.json` / `flow.iteration` is a **step-turn / HOP counter that INCLUDES code steps** and is **not** the same unit as `notor-max-iterations` (LLM turns only). Progress Notices that show "iteration N" surface the HOP counter; do not conflate the two units.
- **Recovery is parent-rooted + chaining-root + overwrite-idempotent (review-resolved).** The top-level scan recovers **`origin: "user"` roots (always)** and **`origin: "chaining"` successors whose `parent_session_id` resolves to an already-terminal predecessor (recovered as roots — Issue-3)**; `run_flow` children are reconciled by the parent's replay via the durable **`child.spawned`/`child.result` ledger** — **reuse** a terminal child's recorded `child.result`, or **resume a non-terminal child in place** (replay its own log) — **never tombstone-and-respawn** (Issue-2), so the child's `once()` `side_effect.committed` markers survive the crash. `origin` is **always set** at creation (never null); recovery treats absent/unexpected origin as a **loud diagnostic**, not a silent skip (Issue-4b). On reload the in-memory `AggregateBudget` cell is **rebuilt** by replaying `turn.complete` `cost_usd`/`token_usage`, and the **stale-window + thrashing counters are rehydrated** from the replayed event/task history (Issue-5/6) — so a cost cap is not reset to full and a near-stale loop is not zeroed. Scratchpad writes are **overwrite-only** (no append) so a re-run reproduces, not duplicates; `next`/`prev` edges may dangle after a re-run and are skipped by consumers. Code-step `callTool`/`callMcpTool` thread `runContext` (incl. a fresh `subtreeConsumed`), so a code-step `run_flow` cannot bypass `max_depth`/the aggregate budget. Code-step timeout defaults to 300 s (overridable via `notor-step-timeout-seconds`; must exceed any inner shell timeout) and **fires only at `await` boundaries** — an unbounded synchronous loop is not interruptible and freezes the plugin; mitigation is authoring guidance + `await` yield points (no Worker isolation in v1 — Issue-7).
